System Blueprint

A self-hosted, offline-first Retrieval-Augmented Generation chatbot starter stack for Raspberry Pi. Combines ChromaDB vector search with Ollama local inference — no cloud dependencies, all data on device.

Supporting source code for the Offline-First AI Stack guide. Clone-and-run starter with optional upgrade to a dual-process production architecture.

Python 3.13 · Flask · FastAPI 43 Tests Passing ChromaDB · Ollama · nomic-embed-text Raspberry Pi 5 Native MIT License

Module Reference
ModuleExportsResponsibility
rag_engine.py RAGEngine Owns ChromaDB client and collection. Wraps ollama.embed and ollama.generate. Config-agnostic — all settings injected via constructor. Methods: embed_text, add_documents, query, generate_answer.
document_loader.py load_text_files() Globs *.txt from a directory (sorted). Splits each file into non-overlapping character chunks of chunk_size (default 500). Returns (chunks, ids) where ids are filename_offset.
api_server.py create_app() Flask application factory. Accepts optional RAGEngine — if None, constructs one from env vars. Registers GET /health, POST /ingest, POST /query.
__main__.py — Entry point for python -m rag_chatbot. Loads .env, creates app via factory, starts Flask on PORT (default 5000) bound to 0.0.0.0.
fastapi_app.py (upgrade) app (FastAPI) Production async backend on port 7860. Routes: GET /api/health, POST /api/ingest, POST /api/query, POST /api/stream (SSE). Constructs its own RAGEngine from env.
pdf_loader.py (upgrade) load_pdf() PDF ingestion via pymupdf. Extracts text from all pages, chunks by character count. Same (chunks, ids) return format as load_text_files.
chat_history.py (upgrade) ChatHistory SQLite-backed chat session storage. Two tables: sessions (id, created_at) and messages (id, session_id, role CHECK IN ('user','assistant'), content, created_at). Methods: create_session, add_message, get_messages.

Upgrade Path

bash scripts/upgrade.sh extends the starter stack to a dual-process production architecture. The script is idempotent — safe to re-run. It checks for existing files before writing and commits the changes.

Gap Analysis
Missing
No document list or delete API Once documents are ingested into ChromaDB, there is no API endpoint to list what's indexed, remove individual documents, or clear the collection. Users cannot inspect or manage the index via HTTP — only by deleting ./chroma_db/ on disk.
Missing
No CLI entry point in pyproject.toml The package exposes no installed command. Users must run python -m rag_chatbot or make run. Adding a [project.scripts] entry (rag-chatbot = "rag_chatbot.__main__:main") would allow rag-chatbot as a shell command after install.
Partial
FastAPI /api/query endpoint undocumented in api.md The upgrade script generates POST /api/query in fastapi_app.py, but docs/api.md does not list it. Only /api/health, /api/ingest, and /api/stream are documented for the FastAPI stack.
Partial
services/rag-chatbot.service undocumented A pre-built systemd service for the starter Flask server exists at services/rag-chatbot.service and is referenced by scripts/install.sh, but setup.md only documents the upgrade-script-generated services (ai-stack-api.service, ai-stack-web.service). The starter service install path is not mentioned.
Partial
No input validation on /ingest POST /ingest does not validate that texts is a non-empty list of strings. Passing null, a plain string, or a malformed body will raise an unhandled exception. Only /query returns a clean 400 error on bad input.
Design
No chunk overlap / stride in document_loader Text is split into non-overlapping fixed-size character chunks. Context at chunk boundaries may be split mid-sentence, degrading retrieval quality. A stride parameter (e.g., 50-char overlap) would reduce boundary loss. Noted as a known limitation of the starter stack.
Design
OLLAMA_HOST env var not explicitly wired in RAGEngine The .env.example documents OLLAMA_HOST and the ollama Python library auto-detects it from the environment. However, RAGEngine.__init__ does not read or validate it. This works implicitly but makes the dependency invisible; a failed Ollama connection surfaces only at first embed/generate call, not at startup.
Out of Scope
Authentication, multi-user, Docker, CI/CD Intentionally out of scope per the design spec. The server binds to 0.0.0.0 with no auth — suitable for local/LAN use only. For production multi-user deployments, see CoreChat.
Frontend Review
Starter Stack — No UI
The base Flask server is a pure JSON API. No HTML is served. All interaction is via curl or API client. This is intentional — the starter stack is designed as a backend building block, not a user-facing product.
After Upgrade — Chat UI
templates/chat.html is added by upgrade.sh and served at GET /chat. CoreConduit brand v2.1 Silver styling (navy background, blue/orange accents, IBM Plex Mono). Vanilla JS — no framework, no bundler.

Limitations: Connects to POST /query (blocking, not SSE). Does not use the FastAPI streaming endpoint. No session management, no message persistence in the UI (chat history is stored server-side but not displayed on reload).
